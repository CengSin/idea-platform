# Feature Map

改功能的 PR 必须同步改本文件里对应的那一节：入口、可见文案、选择器、前置条件、故障现象。新增页面或对话框时加一节；删掉功能时删对应节，不要留过期选择器。

本文件描述当前代码里的可见界面。选择器以源码为准，不发明尚未存在的 `data-testid`。全仓库目前没有任何 `data-testid`。

## 选择器怎么写

优先用无障碍名称，其次用稳定的 `aria-label`、表单 `name`、锚点 id、已有 class。

- 链接和按钮：`getByRole('link', { name: '发现' })`、`getByRole('button', { name: '保存草稿' })`。名称包含可见文字；图标按钮用 `aria-label`。
- 表单字段包在 `<label>` 里，可用标签文字定位，例如「邮箱」「标题」。
- 对话框是 `[role="dialog"]`，**没有** `aria-labelledby`。不能靠对话框的 accessible name 区分。用内部 `h2` 的标题文字区分。点遮罩关闭的按钮是 `button[aria-label="关闭"]`，`Escape` 也会关闭。
- 顶栏「工作台导航」在宽度小于 `md`（768px）时整段隐藏（`hidden md:flex`）。窄屏测「发现 / 我的想法 / 承接中 / 作品」要直接打开 URL，或先把视口拉到桌面宽度。

会话 cookie 名是 `idea_session`。仓库不内置测试账号，本地注册即可。管理员是环境变量 `ADMIN_EMAILS` 里的邮箱（逗号、分号或换行分隔），代码里不写死账号。

## 路由

| 路径 | 谁能打开 | 页面 |
| --- | --- | --- |
| `/` | 已登录。未登录 307 到 `/explore` | 发现（与广场同一组件） |
| `/explore` | 任何人，含已登录 | 想法广场 |
| `/explore/:ideaId` | 任何人；非公开想法 404 | 公开想法 |
| `/explore/people/:userId` | 任何人；该用户没有公开想法则 404 | 公开作者页 |
| `/login`、`/register` | 未登录。已登录按 `next` 跳走 | 登录 / 注册 |
| `/ideas` | 已登录 | 我的想法 |
| `/ideas/new` | 已登录。打开后立刻被替换成 `/ideas` | 创建想法对话框 |
| `/ideas/:id` | 已登录，且该想法在当前用户可见范围内 | 想法详情 |
| `/attempts`、`/attempts/:id` | 已登录 | 承接列表 / 承接详情 |
| `/works`、`/works?mine=1`、`/works/:id` | 已登录 | 作品列表 / 作品详情 |
| `/notifications` | 已登录 | 通知 |
| `/profile` | 已登录 | 个人资料 |
| `/settings` | 已登录 | 设置 |
| `/admin` | 已登录且邮箱在 `ADMIN_EMAILS`。否则重定向到 `/` | 管理 |
| 其他未登录的工作台路径 | 跳到 `/login?next=<原路径>` | — |

公开页和登录页不要求 cookie。`/api/*` 不走这套页面重定向。

## 游客顶栏

- 用户称呼：想法共享.、发现想法、登录、写下想法
- 入口：`/explore` 及其子页顶部。品牌链回 `/explore`
- 关键选择器：`header.explore-header`；品牌 `a[aria-label="Idea Platform 游客首页"]`；`nav[aria-label="游客导航"]`；跳过链接 `a[href="#explore-content"]`；主内容 `#explore-content`
- 子功能：发现想法（`/explore#ideas`，窄屏隐藏 `sm:block`）、登录、写下想法（去 `/register`）
- 前置条件：无
- 常见故障现象：顶栏按钮点了仍停在加载骨架 → 公开目录接口慢或失败，页内会出现「暂时没能加载公开内容」和「重新加载」

## 想法广场

- 用户称呼：发现、想法列表。首页只有这一张画卷，没有「脉络星云 / 策展画卷」切换。`?view=` 会被忽略。
- 入口：游客打开 `/` 或 `/explore`；登录用户打开顶栏「发现」（`/`）。两处渲染同一个 `IdeaJournal`。写下想法在顶栏：登录后去 `/ideas/new`，游客去 `/register`
- 关键选择器：`#ideas`；标题「共享，实现，追踪。」；`[aria-label="筛选想法"]`；`[aria-label="搜索想法或作品"]`；`[aria-label="清除搜索"]`；`[aria-label="想法列表"]`
- 子功能：
  - 筛选「全部 / 待实现 / 迭代中 / 有作品 / 已弃用」。待实现 = 没有承接、没有作品、且未弃用。迭代中 =（有来源作品，或已有承接）且未弃用。有作品 = 至少一件公开作品。已弃用只看想法状态。
  - 搜索匹配标题、简介、问题、作者、标签、作品名。
  - 第一条是焦点卡。其余卡片由 `@egjs/react-grid` 的 `MasonryGrid` 排成等宽瀑布流（`.idea-masonry`，`align="stretch"`，单列最宽约 420px，间距 16px）。卡片状态文案为「待实现 / 实现中 / 已有作品 / 已弃用」。有来源时写「来自作品 …」。有作品时列出作品名。
  - 置顶想法是 `.holo-card`，底图是 `/covers/holo-card-bg.jpg`。指针在卡片外框内移动时做 3D 倾斜，镭射箔和高光跟着走；外框不跟着转，所以划到边缘不会来回弹。离开外框约 28px 后才放平。卡上直接有「打开这个想法」。游客且未弃用时还有「我来实现」，去 `/login?next=/ideas/:id`。登录用户没有这第二个按钮，承接在想法详情里。`prefers-reduced-motion` 时不倾斜。
- 前置条件：只列出公开目录。草稿、未发布想法不会出现。
- 常见故障现象：
  - 筛选「迭代中」里混着「正在做」和「从作品长出来的新想法」→ 这是当前规则，不是数据丢了。
  - 筛选后焦点卡换成了另一条 → 焦点永远是过滤结果的第一条，不是单独精选。
  - 空态「还没有匹配的想法」或「让第一个想法留在这里」。
  - `src/components/graph/FamilyBoard.tsx` 仍在仓库里，首页不再挂载它。

## 公开想法

- 用户称呼：回到想法广场、我想动手实现、分享这个想法
- 入口：广场卡片、作者页一行、`/explore/:ideaId`。作品锚点 `#work-<workId>`，作品区 `#works`
- 关键选择器：`article.journal.journal-detail`；返回 `a.journal-back`；来源条 `.evolution-trail`；正文 `.journal-letter`；参与栏 `.journal-participate`；主按钮 `a.journal-primary`；分享 `button.journal-share`；作品格 `.journal-work-grid`；新方向 / 功能迭代列表 `.public-work-iterations`；弃用提示 `.idea-deprecated-notice`、`.idea-deprecated-badge`
- 子功能：
  - 正文按有无内容出现：我遇到的问题、我希望发生的改变、作者的验收标准、还想一起探索的问题、动手前想补充的几件事。
  - 作品封面、版本号、「打开作品」（新窗口）、「迭代提醒」。
  - 从这个作品长出的新方向、收进版本历史的功能迭代，都链到对应公开想法。
  - 分享把当前 URL 写入剪贴板。成功按钮变成「链接已复制」；失败变成「请复制浏览器地址分享」。状态同时写在 `role="status"` 的屏幕阅读文本里。
  - 作者名链到 `/explore/people/:authorId`（没有 authorId 时只是文字）。
- 前置条件：想法在公开目录中。弃用想法仍可阅读，不显示「我想动手实现」，改为「已弃用，暂不接受新的承接」。
- 常见故障现象：404「这个想法暂未公开」→ 草稿、私密、已删，或 id 错误。来源条写「来源作品暂不可见」→ 上游作品不在公开目录，本页仍保留。

## 公开作者页

- 用户称呼：的开放笔记本、我提出的想法、从这些想法长出的作品
- 入口：公开想法页上的作者名，`/explore/people/:userId`
- 关键选择器：`.journal.journal-creator`；返回 `a.journal-back`（回 `/explore`）；每一行 `a.journal-creator-row`
- 子功能：公开想法列表、这些想法名下的公开作品（作品行跳到该想法的 `#works`）
- 前置条件：该用户至少有一条公开想法，否则 404
- 常见故障现象：页头简介是默认句「在这里分享在意的问题…」→ 用户没有填写 bio

## 登录

- 用户称呼：欢迎回来、登录、立即注册、先逛逛
- 入口：游客顶栏「登录」；未登录访问工作台时 `/login?next=<原路径>`；公开想法「我想动手实现」带 `next=/ideas/:id`
- 关键选择器：`main` 内 `form`；`input[name="email"]`；`input[name="password"]`；隐藏域 `input[name="next"]`；提交按钮「登录」；错误 `[role="alert"]`；「立即注册」；「先逛逛，以游客身份浏览」（`/explore`）
- 子功能：登录中按钮变为「正在登录…」。左侧介绍文案只在 `lg` 及以上显示。
- 前置条件：未登录。已登录打开本页会直接去 `next`（非法或指向 `/login`、`/register` 时去 `/`）。
- 常见故障现象：
  - 「请输入邮箱和密码。」「邮箱或密码不正确。」
  - 登录成功却回到首页而不是刚才的页面 → `next` 不是以单个 `/` 开头的站内路径，被丢掉了。

## 注册

- 用户称呼：创建你的账号、注册并进入、返回登录
- 入口：`/register`，游客顶栏「写下想法」，登录页「立即注册」。同样接受 `?next=`
- 关键选择器：`input[name="displayName"]`、`email`、`password`、`confirmPassword`、`next`；提交「注册并进入」；错误 `[role="alert"]`
- 子功能：昵称、邮箱、密码、确认密码。密码提示「至少 8 个字符」。
- 前置条件：未登录。已登录同样按 `next` 跳走。
- 常见故障现象：「昵称至少需要 2 个字符。」「请输入有效的邮箱地址。」「密码至少需要 8 个字符。」「两次输入的密码不一致。」「该邮箱已注册，请直接登录。」

## 工作台顶栏

- 用户称呼：想法共享、发现、我的想法、承接中、作品、写下想法、通知、管理、设置、个人资料、退出登录
- 入口：所有已登录工作台页面顶部，`header` 粘在上方
- 关键选择器：品牌 `a[aria-label="想法共享首页"]`（去 `/`）；`nav[aria-label="工作台导航"]`；当前项 `a[aria-current="page"]`；通知 `a[aria-label="通知"]` 或 `a[aria-label^="通知，"]`；`a[aria-label="管理"]`；`a[aria-label="设置"]`；`a[aria-label="个人资料"]`；`button[aria-label="退出登录"]`
- 子功能：
  - 四个文字导航只在 `md` 及以上显示。
  - 「写下想法」始终可见，去 `/ideas/new`。
  - 有未读时通知按钮的 accessible name 带未读条数，并显示红点。未读数是当前用户可见通知里 `read !== true` 的条数。
  - 「管理」只在当前邮箱属于 `ADMIN_EMAILS` 时出现。
  - 退出提交后去 `/login`，并清掉 `idea_session`。
- 前置条件：已登录。未登录到不了这个顶栏。
- 常见故障现象：手机上看不到「发现 / 我的想法 / 承接中 / 作品」→ 导航被 `hidden md:flex` 藏起来了，不是账号没权限。

## 我的想法

- 用户称呼：我的想法、新建想法、查看详情
- 入口：顶栏「我的想法」，`/ideas`
- 关键选择器：`h1`「我的想法」；「新建想法」按钮；卡片内链到 `/ideas/:id`；空态「写下第一个想法」链到 `/ideas/new`
- 子功能：只列出当前用户当作者的想法。每张卡片有状态徽标（草稿、已发布、生长中、已实现、已弃用、沉寂、已归档）、更新时间、有效承接数、作品数、衍生数。来自作品的想法显示「源自作品」以及「功能迭代」或「新方向」。
- 前置条件：已登录
- 常见故障现象：空列表但广场上能看到自己的公开想法 → 作者身份对不上当前账号，或想法是别人的。草稿也会出现在这里。

## 创建想法 / 编辑草稿

- 用户称呼：创建一个想法、编辑想法草稿、保存草稿、直接发布
- 入口：顶栏「写下想法」、我的想法「新建想法」、`/ideas/new`、草稿详情「编辑草稿」。`/ideas/new` 打开对话框后马上 `replace` 到 `/ideas`，地址栏不会停在 `/ideas/new`。
- 关键选择器：`[role="dialog"]` 内 `h2`「创建一个想法」或「编辑想法草稿」；标签「标题」「预期效果」「想解决的问题」；折叠「补充说明与执行条件（可选）」；其内「补充价值」「验收标准」「停止条件」；按钮「取消」「保存草稿」或「保存修改」「直接发布」
- 子功能：
  - 新建：有标题即可「保存草稿」；标题、预期效果、想解决的问题都有才能「直接发布」。验收标准和停止条件按行拆开。
  - 编辑草稿没有「直接发布」，只有「保存修改」。发布走草稿条上的「发布草稿」。
  - 成功后进入 `/ideas/:id`。
- 前置条件：已登录。编辑只出现在自己的草稿上。
- 常见故障现象：对话框一闪就回到想法列表 → `/ideas/new` 的设计就是这样，对话框应留在 `/ideas` 上。若对话框也没了，多半是打开动作被路由替换打断，刷新后再点「新建想法」。发布失败的红字出现在按钮上方，没有 `role="alert"`。

## 想法详情（工作台）

- 用户称呼：承接这个想法、标记为弃用、这个想法长成了什么、复制 Idea Context
- 入口：我的想法卡片、承接页的来源链接、作品页「来源想法」、资料页「我提出的想法」。路径 `/ideas/:id`。面包屑第一项「发现」回 `/`
- 关键选择器：草稿条是「编辑草稿 / 删除 / 发布草稿」所在的 `.paper-sheet`；来源条 `.evolution-trail`；标题区按钮「承接这个想法」「为草稿创建项目」「项目已创建」「想法已弃用」；弃用切换「标记为弃用」「恢复这个想法」；实现分支 `section[aria-label="项目实现分支"]`（`.lineage-tree`）；作品区标题「这个想法长成了什么」；上下文栏按钮「复制 Idea Context」；下一步区标题「从这个想法长出的下一步」
- 子功能：
  - 草稿且是作者：编辑草稿、删除（浏览器 `confirm`，确认后回 `/ideas`）、发布草稿。Agent 提交的草稿标题是「Agent 提交的迭代草稿 · 等待你审阅」。
  - 有父想法时显示来源链：上游想法 → 来源作品及版本 →「功能迭代」或「新的方向」。
  - 作者且想法不是草稿、也不是已归档：可标记弃用或恢复。弃用后承接按钮禁用。
  - 已有未放弃的本人承接时，按钮是「项目已创建」且禁用。
  - 实现分支列出未放弃的承接（本人的排在前面）及其作品。没有分支时是虚线空态。
  - 「Agent 可读取的上下文」默认展开「问题」，按钮把 JSON 复制到剪贴板，成功文案「已复制 Idea Context」。
- 前置条件：已登录。别人的草稿不在可见数据里，打开会 404「这条轨道还不存在。」
- 常见故障现象：
  - 「状态更新失败，请重试」出现在弃用按钮旁的 `[role="alert"]`。弃用草稿会得到服务端「请先发布想法」。
  - 分支里看不到已放弃的承接 → 列表会滤掉 `abandoned`。
  - 复制上下文没反应 → 页面没有剪贴板权限。

## 承接对话框

- 用户称呼：承接这个想法、预览承接内容、确认承接
- 入口：想法详情的承接按钮；作品页下一步卡片的「认领下一步」「继续认领」
- 关键选择器：`[role="dialog"]` 内 `h2`「承接这个想法」；只读块「来源 Idea」；「分支名称」「实现方向（可选）」；折叠「覆盖继承内容与其他设置（可选）」；其内「预期效果」「补充价值」「公开程度」（`select`）、「目标日期（可选）」（`input[type="date"]`）；「预览承接内容」「复制提示词」「返回修改」「确认承接」
- 子功能：公开程度选项为公开、不公开列出、仅邀请、私密。预览分「你的承接分支」和「任务预览」。确认后去 `/attempts/:id`。同一想法上已有未放弃承接时，详情按钮直接禁用，打不开这个对话框。
- 前置条件：已登录。想法未弃用。草稿只有作者能建项目。
- 常见故障现象：「该想法已弃用，不能创建新的承接」「草稿仅作者本人可以创建项目」「你已经有一条承接分支，可在「承接中」继续更新。」「承接失败」。这些红字在对话框内，没有 `role="alert"`。

## 承接列表

- 用户称呼：承接中、进入建造看板、前往灵感广场探索
- 入口：顶栏「承接中」，`/attempts`
- 关键选择器：`h1`「承接中」；卡片标题链到 `/attempts/:id`；「起源想法」链到 `/ideas/:ideaId`；空态链接「前往灵感广场探索」（`/explore#ideas`）
- 子功能：只列出当前用户的承接，按最近活动排序。徽标是承接状态（关注中、理解中、原型中、公开测试、已暂停、已沉寂、已放弃、已发布）和公开程度。有阻塞显示第一条；否则有目标日期就显示日期。底部是待办完成数「n/m 项任务」。
- 前置条件：已登录
- 常见故障现象：列表比资料页「我参与的实现」多出已放弃项 → 本页不过滤放弃，资料页会过滤。空列表是「当前没有正在进行的承接」。

## 承接详情

- 用户称呼：最新进展、让 Agent 接管这条分支、待办清单
- 入口：承接列表、想法详情的分支卡、作品页「实现轨道」。路径 `/attempts/:id`。面包屑「承接中」
- 关键选择器：`h1` 为分支名；来源想法链接；「最新进展」；阻塞句以「阻塞：」开头；本人可见两块：Agent 面板、待办面板；作品封面链到 `/works/:id`
- 子功能：状态徽标、开始时间、最近活动、进展原文。草稿来源会多一条说明：发布前仅草稿作者可见。Agent 面板和待办只给分支所有者。
- 前置条件：已登录，且该承接在可见范围内（别人的私密草稿项目可能 404）
- 常见故障现象：进展一直是「Agent 尚未同步进展。」→ `progressNote` 为空，不是页面没加载。看不到待办和 AGENTS.md → 当前用户不是这条分支的所有者。

## 待办清单

- 用户称呼：待办清单、添加、标为完成
- 入口：自己的承接详情页中部
- 关键选择器：标题「待办清单」；复选框 `input[aria-label="标为完成"]` 或 `input[aria-label="标为未完成"]`；待办标题是按钮，点一下变成编辑框；编辑时「保存」「取消」；每行「删除」；底部 `input[placeholder="添加一项待办…"]` 和「添加」
- 子功能：勾选、改标题、删除、新增。右上角「n/m 未完成」或「暂无待办」。添加时客户端生成 id。
- 前置条件：分支所有者，已登录
- 常见故障现象：按钮变成「保存中…」后列表不更新 → 操作失败时红字在表单下，没有 `role="alert"`。待办不会出现在公开广场。

## Agent 连接

- 用户称呼：生成 AGENTS.md、复制提示词、下载最新 AGENTS.md、更新老项目连接
- 入口：
  - 自己的承接详情：「让 Agent 接管这条分支」
  - 自己承接所发布的作品详情侧栏：「更新老项目连接」
- 关键选择器：承接页按钮「生成 AGENTS.md」或「复制提示词」（生成中「正在生成…」，完成后「AGENTS.md 已下载」或「提示词已复制」）；作品页按钮「下载最新 AGENTS.md」或「复制最新提示词」；作品页成功句 `[role="status"]`，失败 `[role="alert"]`
- 子功能：
  - 一级承接（想法没有父想法）：下载 `AGENTS.md`。
  - 从作品衍生的子想法：把完整提示词写入剪贴板，不下载文件。
  - 三步说明：建目录或进入原项目、放入文件或粘贴提示词、启动 Agent。
  - 重新生成不会立刻作废同一分支仍有效的旧 Token。
- 前置条件：该承接的所有者。需要剪贴板权限时（衍生分支）浏览器须允许写剪贴板。
- 常见故障现象：承接页失败只有一段红字「Agent 配置生成失败」，没有 `role="alert"`。作品页失败在 `[role="alert"]`。提示词已复制但 Agent 读不到新接口 → 旧文件还在项目根目录，需要再下载一次替换。

## 作品列表

- 用户称呼：落地的作品、全站作品、我的作品
- 入口：顶栏「作品」，`/works`；只看自己的用 `/works?mine=1`
- 关键选择器：`h1`「落地的作品」；`a[href="/works"]`「全站作品」与 `a[href="/works?mine=1"]`「我的作品」，当前项 `aria-current="page"`；卡片链到 `/works/:id`；角标含 `v{n}` 和类型（Web、应用、影像、文章、研究、艺术、硬件、其他）
- 子功能：封面、来源想法名、简介、紧凑的迭代提醒标签。全站不含草稿想法名下的作品。我的作品只含自己承接分支上已发布的作品，草稿想法名下的也会出现，并写「随想法草稿一起发布」。
- 前置条件：已登录
- 常见故障现象：空态「你的第一个作品，正在路上」或「这里将收集被实现的成果」，按钮「发现想法」去 `/`。全站看不到自己刚保存、尚未发布想法的作品 → 用「我的作品」。

## 作品详情

- 用户称呼：打开作品、来源想法、实现轨道、贡献、作品版本
- 入口：作品列表、承接详情的封面、想法详情的成果卡。路径 `/works/:id`。历史版本用 `?revision=<revisionId>`，对应锚点 `#revision-<revisionId>`
- 关键选择器：封面；状态「已发布 · v{n}」；`h1` 作品名；外链按钮「打开作品」（`target="_blank"`）；侧栏「来源想法」「实现轨道」「贡献」；`details.revision-history`；下一步区 `#next-ideas`
- 子功能：类型、发布日期、署名与许可、版本记录（说明、时间、该版本仓库链接）。版本 `<details>` 在带 `revision` 查询时默认展开，命中的 `<li>` 有 class `revision-selected`。
- 前置条件：已登录，作品可见。侧栏「管理我的作品」和「更新老项目连接」只给该作品所属承接的所有者（`canManage`）。
- 常见故障现象：封面是占位图 → 没有可用的 `coverUrl`，或外链抓不到预览。版本说明写「现有作品，历史未记录」→ 这条修订没有 `recordedAt`。

## 编辑作品 / 删除作品

- 用户称呼：管理我的作品、编辑作品、删除作品
- 入口：作品详情侧栏，仅承接所有者
- 关键选择器：按钮「编辑作品」「删除作品」；保存成功 `[role="status"]`「作品已更新。」；编辑对话框 `h2`「编辑作品」；字段 `name`：`title`、`summary`、`type`、`external_url`、`repository_url`、`cover_url`、`implementation`、`derivatives`、`commercialUse`；「保存修改」。删除对话框 `h2`「删除这个作品？」；「确认删除」。错误 `[role="alert"]`
- 子功能：可改名称、简介、类型、作品链接、仓库、封面、是否允许实现、是否允许衍生、商用（允许商用 / 商用需署名 / 禁止商用）。清空封面，或只改了作品链接、没改封面，会重新抓预览。删除后去 `/works`。删除不碰外站和仓库；若这是该分支最后一个已发布作品，承接从「已发布」回到测试阶段。
- 前置条件：已登录，且是该承接的所有者。请求带登录会话，不是 Agent Token。
- 常见故障现象：保存或删除失败的文案来自接口 `error`，或「操作失败，请稍后重试。」「网络异常，请稍后重试。」非所有者看不到这块面板，直接改接口会 403。

## 下一步

- 用户称呼：从这个作品发布下一步、写下下一步、认领下一步、审阅草稿
- 入口：作品详情底部 `#next-ideas`。首页卡片上的「来自作品」链到公开想法的作品锚点，或登录后的 `/works/:id`。
- 关键选择器：`#next-ideas`；按钮「写下下一步」；卡片上 `button[aria-label^="编辑"]`、`button[aria-label^="删除"]`；认领按钮「认领下一步」「继续认领」或「审阅草稿」；创建对话框 `h2`「从这个作品发布下一步」；单选 `input[name="relationKind"]` 值为 `iterate` 或 `derive`；编辑已发布下一步时 `h2`「编辑下一步」；删除确认 `h2`「删除这个下一步？」
- 子功能：
  - 关系二选一：「优化现有作品的功能/体验」（功能迭代，收进版本历史）或「一个新的方向 / 独立产出物」（图谱上的新分支）。提交后不能改这个判定。
  - 字段：下一步标题、本轮改什么、为什么改；可选补充价值、验收标准、停止条件（按行拆）。
  - 「保存草稿」只在新建时出现，草稿仅作者可见。卡片徽标「私有草稿」。公开发布用「公开发布」。
  - 阶段徽标：萌芽、成长、结果。有承接或作品时删除按钮禁用，title 为「已有关注、承接或作品，不能删除」。
  - 草稿的编辑走「编辑想法草稿」对话框，不走下一步编辑器。
- 前置条件：「写下下一步」只给该作品承接的所有者。其他人仍能看到已公开的下一步并认领。
- 常见故障现象：没有「写下下一步」→ 不是所有者。删除确认后失败红字「删除失败」，没有 `role="alert"`。空态「下一步还没有被写出来」。

## 通知

- 用户称呼：通知、全部标为已读
- 入口：顶栏铃铛，`/notifications`。没有顶栏文字导航项。
- 关键选择器：`h1`「通知」；按钮「全部标为已读」；每一条是链到 `notification.href` 的 `a.glass`；未读标题前有一个圆点
- 子功能：打开本页不会自动标已读，要点按钮。点击一条去它自己的 `href`。
- 前置条件：已登录。列表来自当前用户可见数据里的通知。
- 常见故障现象：铃铛有红点但列表是空的 → 未读计数和列表都走可见通知；若不一致，先看是不是顶栏未读数在进入页面前就被别的请求刷新掉。按钮在请求期间禁用，没有成功提示。

## 个人资料

- 用户称呼：我的开放笔记本、邮箱、添加外部项目、我提出的想法、我参与的实现、我带回的作品
- 入口：顶栏头像 `a[aria-label="个人资料"]`，`/profile`。设置页也有「打开个人资料」
- 关键选择器：`h1`「我的开放笔记本」；邮箱区按钮「复制」/「已复制」，邮箱本身是 `mailto:` 链接；外部项目 `input[name="title"]`、`input[name="url"]`、提交「添加」；移除 `button[aria-label="移除项目连接"]`；作品外链 `a[aria-label="打开作品站点"]`

  - 想法列表不含草稿。承接不含已放弃。作品含自己承接的，以及署名里有自己的已发布作品。
  - 外部项目要名称和 `http(s)` URL。错误在 `[role="alert"]`。

## 设置

- 用户称呼：设置、打开个人资料、清空全部内容数据
- 入口：顶栏齿轮 `a[aria-label="设置"]`，`/settings`
- 关键选择器：`h1`「设置」；「打开个人资料」；危险按钮「清空全部内容数据」（进行中「正在清空…」）

## 加载、出错、找不到

- 用户称呼：正在加载页面…、页面暂时没能加载、这个想法暂未公开、这条轨道还不存在
- 入口：路由切换时的骨架；渲染异常；未知 id
- 关键选择器：加载容器 `[role="status"]`，屏幕阅读文字「正在加载页面…」。工作台或根错误 `[role="alert"]`，按钮「重新加载」，链接「公开广场」。公开页错误标题「暂时没能加载公开内容」，按钮「重新加载」。公开 404 标题「这个想法暂未公开」，链接「浏览其他公开想法」。工作台 404 文案「这条轨道还不存在。」，链接「回到发现」
- 子功能：无
- 前置条件：无
- 常见故障现象：公开想法 404 的说明「它可能已被移除，或仅对受邀成员可见。」也用于草稿和错误 id，不能据此判断可见性设置。

## Agent HTTP API

- 用户称呼：无页面。人从承接页或作品页拿到 `AGENTS.md` / 提示词后再调用
- 入口：`/api/v1/...`。页面中间件不拦截 `/api`
- 关键选择器：无 DOM。写操作要 `Authorization: Bearer <分支 Token>` 和 JSON 里的 `user_confirmed: true`（严格布尔）。网页上的编辑作品、删除作品走登录会话调用同一作品接口。
- 子功能：

  | 方法 | 路径 | 做什么 |
  | --- | --- | --- |
  | `POST` | `/api/v1/ideas` | 创建想法；`as_draft: true` 存草稿 |
  | `PATCH` / `DELETE` | `/api/v1/ideas/:id` | 改草稿或删自己的草稿。`publish: true` 只接受网页确认 |
  | `GET` | `/api/v1/ideas/:id/context` | Idea Context |
  | `POST` | `/api/v1/attempts` | 承接 |
  | `GET` / `PATCH` | `/api/v1/attempts/:id` | 读或更新承接 |
  | `GET` | `/api/v1/attempts/:id/bootstrap` | 最新能力、约定、分支上下文 |
  | `GET` / `POST` / `PATCH` / `DELETE` | `/api/v1/attempts/:id/todos` | 待办。待办本身不是发布授权 |
  | `POST` | `/api/v1/works` | 发布作品 |
  | `GET` / `PATCH` / `DELETE` | `/api/v1/works/:id` | 读、改、删自己分支的作品 |
  | `GET` / `POST` | `/api/v1/works/:id/iterations` | 读或提交迭代草稿 |
  | `GET` | `/api/v1/export` | 导出 |

- 前置条件：Token 属于那一条承接。Agent Token 不能发布想法。公开写操作要用户明确授权（`user_confirmed: true`）。
- 常见故障现象：401 凭证无效；403 不是所有者或 Token 分支不匹配；404 对象不存在；400 参数无效；415 Content-Type 不是 JSON。同一分支重试应复用原来的 `request_id`。Token 临近到期且仍在使用时会续期；重新下载配置不会立刻吊销仍有效的旧 Token。
