# Feature Map

改功能的 PR 必须同步修改本文件里对应的那一节，包括入口、可见文案、选择器、前置条件和故障现象。全仓库没有 `data-testid`，优先用无障碍名称和 `aria-label` 定位。

## 路由

| 路径 | 谁能打开 | 页面 |
| --- | --- | --- |
| `/` | 任何人 | 公开项目页（ISR 10 分钟） |
| `/login` | 任何人；已登录直接跳 `/admin` | 后台登录 |
| `/admin` | 已登录；否则跳 `/login` | 项目后台 |
| `/api/v1/projects` | 任何人 | 公开项目 JSON |
| `/api/cron/sync` | `Bearer $CRON_SECRET` | 每日同步 |
| `/api/owner/showcase` | `Bearer $ADMIN_PASSWORD` | GET 读全部数据（`?sync=1` 先同步）；POST 保存评选结果，供远程 `npm run curate` 使用 |

会话 Cookie 名为 `showcase_session`，是一个签名的过期时间戳，没有账号表。

## 公开项目页

- 关键选择器：`h1`「<名字> 的项目」；区块标题 `#featured`「最有想象力」、`#building`「正在推进」、`#others`「其他项目 · N」（`<details>`，默认折叠）；卡片内链接「打开」（有 homepage 时）、「源码」；柱状图 `svg[role="img"]`，其无障碍名称为「最近 12 周共 N 次提交」。
- 规则：私有、Fork、隐藏、已不在 GitHub 的仓库，以及 `owner/owner` 个人主页仓库，都不会出现。精选 = 置顶项目 + 想象力 ≥ 55 分的项目，按分数排序，最多 6 个（置顶项目不受数量限制）。「正在推进」= 其余项目中最近 14 天有提交的。状态：推进中 ≤14 天，放缓 ≤60 天，之后为沉睡；已归档仓库单独标出。
- 常见故障现象：显示「还没有同步任何仓库」→ 存储为空，需要在后台同步或运行 `npm run curate`。修改后公开页没有变化 → 本地脚本写入不会触发重新验证，最多等 10 分钟。

## 后台登录

- 关键选择器：`input[name="password"]`、按钮「登录」，错误信息在 `p[role="alert"]`（「密码不正确。」或「服务端还没有设置 ADMIN_PASSWORD。」）。

## 项目后台

- 顶栏：「查看公开页」「从 GitHub 同步」（同步中显示「正在同步…」，结果在 `role="status"` 或 `role="alert"` 里）、「退出」。
- 筛选 `[role="tablist"][aria-label="筛选项目"]`：全部、公开精选、推进中、待评选、私有、已隐藏、Fork / 已移除；搜索框「搜索名称、简介、笔记」；排序 `select`：按想象力 / 按最近活动。
- 每一行：分数徽标（未评选显示「未评」）、仓库名、徽标（公开精选、Fork、已不在 GitHub、已隐藏、「有新推送，待重评」）、状态和语言；按钮 `aria-label`：「置顶到公开精选」/「取消置顶」（私有仓库显示「私有仓库不会公开展示」，点击无效）、「在公开页隐藏」/「在公开页显示」、「笔记与评选详情」。
- 详情面板：Claude 的评选（pitch、理由、评选时间）、最近提交；表单字段「公开一句话」（最多 80 字）、「私人笔记」（最多 4000 字，只在后台显示），按钮「保存」，保存成功后显示「已保存」。
- 常见故障现象：同步报 GitHub 403 或频率超限 → 配置 `GITHUB_TOKEN`。看不到私有仓库 → 服务端没有配置 `GITHUB_TOKEN`（本地 `npm run curate` 会用 gh 的登录态同步）。
